## tests/
- **Responsibility:** Standalone CMake + CTest project (`bootloader_host_tests`, C11, `-Wall -Wextra` / `/W4`) that builds `src/boot/{crc32,image_validate,can_update,dfu_config}.c` as a `boot_core` static library with no hardware includes, links each `test_*.c` against it plus vendored Unity, and registers each as a CTest test. Runs on x86; no target toolchain needed. 100 tests in total (6 + 41 + 31 + 22).
- **Key files:** `CMakeLists.txt`, `test_crc32.c`, `test_image_validate.c`, `test_can_update.c`, `test_dfu_config.c`
- **Relationships:** imports from `src/boot/` (crc32, image_validate incl. `boot_decide` and the update plan, can_update, dfu_config); depends on `tests/unity/`. Usable standalone (`cmake -S tests -B build-host`) or via `add_subdirectory(tests)` from the root `CMakeLists.txt`.

- **CMakeLists.txt** — Builds the `unity` and `boot_core` static libraries and defines `add_host_test(name)`, which compiles, links and registers each test (4 registered: test_crc32, test_image_validate, test_can_update, test_dfu_config).
- **test_crc32.c** — 6 tests of `crc32_ieee` and `crc32_ieee_update`: the "123456789" check value, empty input, single byte, an all-0xFF write unit, update over any split equals one-shot, and an empty chunk is the identity.
- **test_image_validate.c** — 41 tests.
  - `image_validate()` against a fake flash buffer: valid, erased or bad magic, header-CRC corruption, size zero / below min / above slot / exactly slot, SP below / at SRAM base / above end / not 8-byte aligned, entry in the bootloader or metadata block / past image end / inside the vector words / right after them / at the last halfword / Thumb bit clear, payload-CRC corruption.
  - Bounds checks without a record, staged images (vector unit still erased in flash, CRC mismatch, RAM vectors checked), metadata encode/layout.
  - `boot_decide()`: valid record, valid record + marker, marker without record, marker + torn record, no record with valid or erased SP, corrupt record, torn marker, one-wrong-word marker.
  - `update_start_plan()`: a retry after an interrupted update keeps the marker; a valid or completed record and a bootable-SP no-record erase the metadata only; a torn or failing record and erased flash erase the app first.
- **test_can_update.c** — 31 tests of `can_update_handle_frame()` against a fake NOR-flash HAL that enforces erase-before-program and write alignment:
  - Basic flow: other CAN IDs ignored, HELLO ACK (version + slot size), wrong version, full happy path, out-of-order commands, GO before VERIFY, size out-of-bounds NAKs, seq-gap rewind.
  - VERIFY: CRC mismatch (metadata left erased), bad vectors despite a matching CRC.
  - Recovery: erase/program/verify flash failures with restart recovery, HELLO restart mid-transfer.
  - Frame acceptance: malformed DLC, only padded protocol frames accepted, DATA ignored outside a transfer, INFO left to the integration layer.
  - Idempotent re-ACKs of repeated SIZE/ERASE/VERIFY and of the final window.
  - The vector unit kept erased until VERIFY, then programmed once.
  - Flash ownership: the DFU flash lock NAKs SIZE/ERASE/DATA/VERIFY; ownership runs from SIZE until HELLO; `end_session` releases flash.
  - A custom per-device command ID is matched while the default is ignored.
- **test_dfu_config.c** — 22 tests of `dfu_config_parse()` and `dfu_config_can_ids()` against a fake config blob:
  - Names: v1/v2 round-trips, erased or bad magic, unknown version, manufacturer/product length over max (and exactly max allowed), bad CRC, mutated payload or IDs without a CRC fix, empty strings.
  - CAN IDs: defaults for an absent block, a v1 block and a bad-CRC v2 block; provisioned v2 IDs; boundary IDs accepted; out-of-range IDs fall back per field; a mixed pair falls back only the bad field; equal IDs, or a command ID equal to the default reply ID, fall back to the defaults.
