### tools/can-flash/
- **Responsibility:** Host-side Python CLI that streams a `.bin` application image to the UNO R4 Minima (RA4M1) CAN bootloader over classic CAN 2.0B, implementing CAN Update Protocol v1 (HELLO → SIZE → ERASE → DATA windows → VERIFY → GO), plus a built-in selftest that exercises the protocol against an in-process fake bootloader.
- **Key files:** `can_flash.py`, `README.md`, `requirements.txt`
- **Relationships:** imports `can` (python-can, external, pinned `>=4.0`). No code-level dependency on other repo directories — protocol constants (`CMD_*`, error codes, `EXPECTED_SLOT_SIZE = 0x0003B800`, `FLASH_BLOCK_SIZE = 2048`) must be kept frozen in lockstep with the bootloader's `src/boot/can_update.c`.

- **can_flash.py** — Single-file CLI + library. Defines CAN Update Protocol v1 constants (command opcodes, error codes, 2048-byte blocks split into 342 six-byte DATA frames per window). `CanFlasher` drives the handshake/erase/transfer/verify/go sequence over a python-can `Bus` with retry-on-timeout, NAK-driven window rewind (seq-gap recovery), and TX backpressure handling (ENOBUFS/"buffer full" retry loop). `FakeBootloader` (a thread) simulates the firmware over the `virtual` interface for `--selftest`, including a forced frame drop to exercise rewind. Top-level `flash_image`, `run_selftest`, `parse_args`, `load_image`, `main`. Runnable directly or as a PEP 723 inline-metadata script.
- **README.md** — Wiring (external 5 V CAN transceiver required — TJA1050/MCP2551/MCP2562, 120 Ω termination), entering CAN update mode (app writes magic `0xB007CAFE` to `VBTBKR[4]` and resets, or boots with no valid app), per-adapter CLI examples (socketcan/slcan/gs_usb), options table, and a protocol summary mirroring `can_flash.py`.
- **requirements.txt** — Single pinned dependency: `python-can>=4.0`.
