- **build.md** — Build and flash guide.
  - **Vendored components and prerequisites:** version table (fork commit, tinyusb 0.17.0 + the fork patch, FSP/CMSIS_5 pins, `ra4m1-headers`) with fetch commands; xPack gcc 14.2.1, GNU make + POSIX sh, a space-free path via `subst`.
  - **Build:** direct-Make invocation with the Windows-specific arguments, the CMake wrapper (`bootloader` target, host `ctest`), and an LTO/zstd `_build/` caveat.
  - **Size gate:**
    - The link fails first through the Minima-only `ra4m1_minima_boot.ld` (FLASH 0x4000, asserted), then the Makefile gate at 16,384 B.
    - Current output: `SIZE GATE OK: 15236 / 16384 bytes` (1,148 B headroom); `CAN_DIAG=1` fits at 15,860 B.
    - Space reclaimed: `BOOT_LOW_FLASH` code at 0x00C0–0x034F (the link fails if it reaches 0x400), no `r_flash_lp` API table, GPIO LED instead of the GPT fade, no FSP `.version` records.
  - **Pre-flash check:** OFS0/OFS1/Security-MPU bytes at 0x400–0x43F against `reference/dfu_minima.hex`.
  - **Flashing:** rfp-cli in ROM boot mode or pyOCD over SWD; unbrick by reflashing `dfu_minima.hex`. Flashing an app over SWD must also erase the `0x3F800` block, or a stale record parks the board.
  - **Boot decision:**
    - `VBTBKR[0]` double-tap → USB DFU.
    - `VBTBKR[4]` = `CAN_UPDATE_MAGIC` → CAN-only update mode, with a 20 s idle timeout counted only on accepted frames (INFO counts only after HELLO).
    - Otherwise `boot_decide`: valid record → app; failing record or marker → parked DFU + CAN; neither → stock SP check.
  - **Protocol:**
    - unaccepted frames get no reply;
    - exact repeats of SIZE/ERASE/VERIFY and the final DATA window are re-ACKed;
    - SIZE < 8 B is NAKed `0x04`, and VERIFY checks SP/entry;
    - a DATA/VERIFY flash failure ends the session.
  - **Flash-owner interlock:** CAN and DFU never write flash together. Ownership is released by a reset, a new HELLO/download/abort, unplug or re-enumeration, or 20 s without activity.
  - **Per-device CAN IDs:** config block v1/v2 with per-field fallback; the data-flash read gate (closed by any failed erase/program); the transceiver-rail power-up; the INFO wire format.
  - **Checked USB DFU download:**
    - only alt 0 accepts downloads;
    - full 64 B blocks in order from block 0, nothing at `0x3F800`;
    - every erase/write is read back;
    - at manifest the received CRC must equal the flash CRC and SP/entry must pass, otherwise `errVERIFY` / `errFIRMWARE`.
  - **Update-in-progress marker and deferred vector unit:** `update_start_plan` decides what to erase before the marker; the app's first 8 bytes are programmed only at commit; the power-loss table.
