Custom bootloader for the Arduino UNO R4 Minima (Renesas RA4M1): a fork of
Arduino's stock TinyUSB DFU bootloader with four added features — flashing an
application `.bin` over classic CAN on D4/D5, flash-time-configurable USB DFU
manufacturer/product names, per-device CAN update IDs (so multiple boards can
sit in bootloader mode on one bus and be addressed individually), and recovery
from an interrupted flash (an update-in-progress marker plus a 15 s CAN idle
timeout park the board in DFU + CAN instead of booting a half-written image).
The image is 14,232 of 16,384 bytes; code also fills the 0xC0–0x3FF gap below
the option bytes.

## Architecture Overview

- **src/** — The bootloader's own C sources: a pure-C11 logic core (`boot/`: memory map and `BOOT_LOW_FLASH` placement, image record and update-in-progress marker, CRC32, image validation and `boot_decide()`, the CAN Update Protocol v1 engine, per-device CAN-ID and DFU-name config parsing) plus the single hardware driver it needs (`drivers/can_polled.c`, a polled RA4M1 CAN0 driver whose init/send/deinit sit in the low-flash gap).
- **tests/** — Standalone CMake/CTest project building `src/boot/*.c` as a library and unit-testing every pure-logic module on x86 via vendored Unity, including every `boot_decide()` outcome — no target hardware required.
- **tools/** — Host-side python-can CLI/TUI (`can-flash/`) that flashes an application image to the bootloader over CAN (Protocol v1, the same one in `src/boot/can_update.c`), and can also identify (`--info`), scan (`--scan`), and remotely reboot boards into the bootloader (`--enter-bootloader`).
- **docs/** — Build/flash guide (size gate, option-byte check, boot decision, idle timeout, update-in-progress marker), the dated research/decision document, and byte-exact reference artifacts (stock hex, reference linker script) for verification and unbricking.
- **scripts/** — Linux build helper (`ci-build.sh`): fetches the gitignored deps and runs the Make build + size gate.
- **.github/** — GitHub Actions workflow that builds the firmware on push/PR and publishes a release titled `c-cpp/ra4m1 vX.Y.Z` on `c-cpp-ra4m1-v*` tags.
- **vendor/** — Vendored third-party build inputs: Arduino's `arduino-renesas-bootloader` fork (where `src/` is integrated: boot decision, flash HAL, CAN service loop, GPIO status LED), tinyusb 0.17.0 (its RA `fsp.ld` places `.text.boot_low_flash` below the option bytes), Renesas FSP, ARM CMSIS_5, and standalone RA4M1 device headers.

The pure-logic `src/boot/` core is developed and tested on the host, then compiled into the vendored `arduino-renesas-bootloader` fork (behind the `CAN_LOADER` and `DFU_CUSTOM_NAME` Makefile flags) to produce the firmware image; `tools/can-flash/` is the host counterpart that speaks the CAN update protocol to the flashed device.
