Host-side Python tooling: a CAN flashing/scanning/TUI client for the CAN updater, and a stdlib-only builder/inspector for ECB update packages.

### tools/can-flash/
- **Responsibility:** Host CLI and Textual TUI that streams a `.bin` to the updater over classic CAN (Protocol v1: HELLO, SIZE, ERASE, DATA windows, VERIFY, GO), identifies boards, scans CAN ID ranges, and reboots running ESP32-S3 apps into their CAN updater. Also contains an in-process selftest with fake bootloader/app simulators.
- **Key files:** can_flash.py, requirements.txt
- **Relationships:** imports from: can (python-can), isotp (lazy, only in `enter_bootloader`), textual (TUI only), stdlib — exposes: `CanFlasher` (protocol client class), `flash_image`, `scan_boards`, `probe_info`, `enter_bootloader`, `FakeBootloader`, `FakeApp`, `run_selftest`, `run_scan_selftest`, `run_tui`, `main`. Protocol constants (`PROTOCOL_VERSION = 0x01`, `CMD_HELLO`…`CMD_ENTER_UPDATER`, `ERR_*`) mirror the device-side update protocol.

- **can_flash.py** — Single-file host tool: the `CanFlasher` protocol client, flash/scan/enter-bootloader/app-control operations, in-process selftests with fake bootloader and app, and the Textual `FlasherApp` TUI; `main()` dispatches headless flags or launches the TUI when run with no arguments.
- **requirements.txt** — Pins the runtime dependencies (python-can>=4.0, pyserial>=3.0, can-isotp>=2.0, textual>=0.60); the same set is also declared inline in can_flash.py's PEP 723 header.
- **README.md** — Wiring, TUI/CLI usage, and adapter notes for can_flash.py.

### tools/pkg/
- **Responsibility:** Standard-library-only builder and inspector for the unsigned ECB package v1 (manifest of one optional BRAIN and up to eight NODE ESP32-S3 app images, with per-entry SHA-256 and a manifest CRC32). Rejects non-ESP32-S3 or bootloader/merged images.
- **Key files:** ecb_pkg.py, README.md
- **Relationships:** imports from: stdlib only (argparse, hashlib, json, pathlib, struct, zlib) — exposes: `build`, `inspect`, `check_image`, `manifest_check`, `can_id`, `node_spec`, `main` (CLI subcommands `build` and `info`). Wire format is documented in docs/reference/package-format.md; the committed vector tests/vectors/sample.ecbpkg is parsed by the C test test_update_pkg.

- **ecb_pkg.py** — Builds ECB package v1 files from brain/node `.bin` inputs (`build`) and verifies an existing package's manifest, ranges, and payload SHA-256 as JSON (`info`); stdlib only, no signing or encryption.
- **README.md** — Usage for `ecb_pkg.py` build/info, upload via curl to `/package`, and the parser interoperability vector.
