# src/

The bootloader's own C sources: a pure-logic, host-testable core under `boot/`
(image-header layout, CRC32, image validation, the CAN Update Protocol v1
engine, and DFU config-block parsing for USB names + per-device CAN IDs) plus
the single hardware driver it depends on, a polled RA4M1 CAN0 driver under
`drivers/`.

## boot/
- **Responsibility:** Pure-C11 logic core of the bootloader — memory-map/config constants, image metadata layout, CRC32, image validation, the CAN Update Protocol v1 engine (incl. reserving the INFO command for the integration layer), and DFU config-block (v1/v2) parsing for custom USB names and per-device CAN IDs. No flash or peripheral access anywhere in this directory — every file compiles and is unit-tested on the host.
- **Key files:** `memory_map.h`, `boot_config.h`, `image_header.h`, `crc32.{c,h}`, `image_validate.{c,h}`, `can_update.{c,h}`, `dfu_config.{c,h}`
- **Relationships:** Depends only on `<stdint.h>`/`<stdbool.h>`/`<string.h>`. `image_validate.c` and `can_update.c` both use `crc32_ieee` and `image_header.h`'s `image_meta_t` layout; `dfu_config.c` falls back to `boot_config.h`'s `CAN_ID_HOST_TO_BOOT`/`CAN_ID_BOOT_TO_HOST` defaults. Consumed by `tests/` (host unit tests) and by the vendored bootloader's `main.c` (CAN service loop + USB descriptor setup), which also supplies `can_update`'s flash HAL and reads `dfu_config`'s parsed CAN IDs to configure `drivers/can_polled.c`'s RX filter.

- **memory_map.h** — Single source of the flash/RAM partition (bootloader region, app slot, metadata block, data-flash DFU config block, SRAM bounds) as `#define`s plus `_Static_assert` consistency checks; must match the vendored linker script.
- **boot_config.h** — Compile-time defaults for the CAN update transport (`CAN_ID_HOST_TO_BOOT`/`CAN_ID_BOOT_TO_HOST`, `CAN_BITRATE_BPS`) and the two handoff/image magics (`CAN_UPDATE_MAGIC`, `IMAGE_META_MAGIC`).
- **image_header.h** — Defines the 16-byte `image_meta_t` little-endian metadata record (magic, image_size, image_crc32, header_crc32) with a `_Static_assert` on its exact size.
- **crc32.h / crc32.c** — `crc32_ieee(data, len)`, IEEE 802.3/zlib-compatible; table-less bitwise implementation chosen to save bootloader flash over a lookup table.
- **image_validate.h / image_validate.c** — `image_validate()` and the ordered `image_validate_result_t` enum (magic → header CRC → size → SP → entry → payload CRC): fail-closed checks of the metadata block and app vector table via explicit little-endian loads, ending in a payload CRC32 check, over a flash-base byte buffer.
- **can_update.h / can_update.c** — The CAN Update Protocol v1 engine: `can_update_hal_t` (flash-erase/program/base HAL seam), state/phase/action enums, `can_update_init()`, `can_update_handle_frame()`. Per-command handlers (HELLO/SIZE/ERASE/DATA/VERIFY) with fail-closed phase transitions, ACK/NAK reply construction, DATA windowing/reject-and-rewind, and a VERIFY commit-point write of the metadata block; documents windowing and the per-device cmd/reply ID model and reserves command `0x07` (INFO) for the integration layer.
- **dfu_config.h / dfu_config.c** — The frozen v1(76B)/v2(80B) DFU config-block layout (magic, version, mfr/prod string fields, v2 CAN-ID fields, CRC trailer). `dfu_config_validate` (magic/version/length/CRC, shared by both accessors); `dfu_config_parse()` returns the USB manufacturer/product strings; `dfu_config_can_ids()` defaults to `boot_config.h` IDs and overrides per-field from a valid v2 block. Shared contract with the ESP-Prog-2 provisioning flasher.

## drivers/
- **Responsibility:** The single hardware peripheral driver the bootloader touches directly — a register-level, polling-only CAN0 driver on D4/D5 for the RA4M1, with zero interrupts and no static-init-order dependencies.
- **Key files:** `can_polled.{c,h}`
- **Relationships:** Depends on vendored RA4M1 headers (`bsp_exceptions.h`, `R7FA4M1AB.h` under `vendor/ra4m1-headers/`). Its frame-level API (`can_polled_receive`/`can_polled_send`) is fed to/from `boot/can_update.c`'s engine by the vendored bootloader's `main.c` CAN service loop, which also supplies the RX filter ID sourced from `boot/dfu_config.c`. `boot/` never includes `drivers/`.

- **can_polled.h** — `can_polled_status_t` and the driver API: `can_polled_init(bitrate, rx_filter_id)`, `can_polled_receive()`, `can_polled_send()`, `can_polled_deinit()` — 250k/500k bit/s, 11-bit standard IDs only, exact single-ID RX filtering.
- **can_polled.c** — Register-level implementation: module-stop release, D4/D5 pin-function-select via PWPR-guarded PFS writes, reset/halt/operate mode sequencing, bit-timing (BCR) setup for 24 MHz PCLKB, RX-FIFO ID-compare/mask configuration, polled TX via mailbox 0 with SENTDATA wait, polled RX via FIFO mailbox 28, and bus-off detection with self-reinitializing recovery.
