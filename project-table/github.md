### .github/workflows/
- **Responsibility:** Defines the single CI and release pipeline for the ESP32-S3 branch (build, artifact upload, release publish).
- **Key files:** `esp32-build.yml`
- **Relationships:** imports from: `tests/CMakeLists.txt`, `build.sh`, `idf-version.txt`, `examples/bench_app/`, `examples/slcan_bridge/`, `node_updater/`, `brain/` — exposes: nothing

- **esp32-build.yml** — Workflow `esp32-build`. Triggers: `push` to branch `version/c-cpp/esp32` and tags `c-cpp-esp32-v*`; `pull_request` targeting `version/c-cpp/esp32`. Permissions: `contents: read` at top level. Job `build` (ubuntu-24.04, Python 3.12): runs host tests (`cmake -S tests -B build-host`, build, `ctest`); caches `.tools` keyed on runner OS, Python version, and `hashFiles('idf-version.txt')`; runs `./build.sh` (node_updater, then brain) and `./build.sh` for `examples/bench_app` and `examples/slcan_bridge`; stages `node_updater/build` outputs (`can_updater.bin`) into `dist/node/` and `brain/build` outputs (`brain_ota.bin`) into `dist/brain/`, each with bootloader, partition table, `ota_data_initial.bin`, `flash_args`, `flasher_args.json`; uploads artifacts `esp32s3-node-updater` and `esp32s3-brain`. Job `release` (needs `build`, runs only on `refs/tags/c-cpp-esp32-v*`, `contents: write`): downloads both artifacts, zips each board into `esp32s3-node-updater-<version>.zip` and `esp32s3-brain-<version>.zip`, and runs `gh release create <tag> --generate-notes` attaching both zips plus loose `can_updater.bin` and `brain_ota.bin`. Release tag pattern: `c-cpp-esp32-v*`; release version = tag minus `c-cpp-esp32-` prefix (e.g. `c-cpp-esp32-v1.0.0` gives `v1.0.0`).
