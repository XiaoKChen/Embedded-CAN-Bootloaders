- **C_STANDARD:** gnu17 for firmware (ESP-IDF v5.3.6 default, `tools/cmake/build.cmake`); C11 for host tests (`tests/CMakeLists.txt`: `CMAKE_C_STANDARD 11`)
- **CXX_STANDARD:** C++ only in `components/arduino_node_app/` (C++17 subset, no exceptions/RTTI/heap), compiled by the consuming Arduino-ESP32 app's PlatformIO toolchain, never by the ESP-IDF projects here
- **TOOLCHAIN:** `xtensa-esp32s3-elf-gcc` from Espressif `xtensa-esp-elf` esp-13.2.0_20250707 (installed by ESP-IDF into `.tools/espressif`); host tests use the system C compiler
- **BUILD_SYSTEM:** ESP-IDF CMake + Ninja via `idf.py`, wrapped by `build.ps1` / `build.sh` (pinned `idf-version.txt` = v5.3.6, repo-local `.tools/`); host tests: CMake ≥ 3.20 + CTest; firmware projects require CMake ≥ 3.16. `node_updater` pulls `espressif/esp_tinyusb` 1.7.6 (with `espressif/tinyusb` 0.21.0~2) through the IDF component manager (`node_updater/main/idf_component.yml`, `node_updater/dependencies.lock`), so its first build needs network. PlatformIO consumers build the library through `library.json` + `platformio/library_build.py`
- **TARGET_MCU:** ESP32-S3 (`CONFIG_IDF_TARGET="esp32s3"`): one shared bootloader + updater for every board; SOLO IDU ESP32-S3-WROOM-1U-N16R8 (16 MB, `partitions_idu_16MB.csv`), SOLO ODU ESP32-S3FH4R2 (4 MB, `partitions.csv`); flash size patched per board by esptool at write time
- **CPU_FLAGS:** set by ESP-IDF for esp32s3 (dual-core Xtensa LX7); none overridden in the repo
- **SOURCE:** `idf-version.txt`, `*/sdkconfig.defaults`, `*/CMakeLists.txt`, `tests/CMakeLists.txt`, `node_updater/main/idf_component.yml`, `library.json`, `.tools/esp-idf/tools/cmake/build.cmake`, `.tools/espressif/tools/xtensa-esp-elf/`
