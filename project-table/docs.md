Documentation for the fork: build/flash/unbrick instructions, the CAN update and interrupted-flash recovery behaviour, the dated research and decision record behind the CAN-update design, and byte-exact reference artifacts (stock hex, reference linker script) used to check that the custom bootloader never corrupts option-setting memory.

### docs/
- **Responsibility:** How to fetch the vendored dependencies and build and flash the UNO R4 Minima DFU + CAN bootloader (Windows Make/toolchain workarounds, size gate, pre-flash option-byte check), and the specification of the CAN update path: boot decision, idle timeout, per-device CAN IDs, INFO, the update-in-progress marker.
- **Key files:** `build.md`, `research/r4-minima-can-bootloader.md`, `reference/dfu_minima.hex`, `reference/minima_fsp.ld`
- **Relationships:** describes `src/boot/memory_map.h` (`BOOT_SIZE`, `BOOT_LOW_FLASH`), `boot_config.h` (`CAN_UPDATE_IDLE_TIMEOUT_MS`), `image_header.h`, `image_validate.h` (`boot_decide`), `can_update.h` and `dfu_config.{c,h}`; the build target `vendor/arduino-renesas-bootloader/` (`Makefile.minima`, `src/main.c`) and `vendor/tinyusb/`; and `tools/can-flash/can_flash.py` as the host counterpart.

- **build.md** — Build and flash guide.
  - **Vendored components and prerequisites:** version table (fork commit, tinyusb 0.17.0 + the fork patch, FSP/CMSIS_5 pins, `ra4m1-headers`) with fetch commands for the `.gitignore`d deps; xPack gcc 14.2.1 (gcc 7.2.1 still builds but larger), GNU make + POSIX sh, a space-free path via `subst`.
  - **Build:** direct-Make invocation with the Windows-specific arguments, the CMake wrapper (`bootloader` target, host `ctest`), and an LTO/zstd `_build/` caveat.
  - **Size gate:** fails if the `.bin` exceeds 16,384 B. Current `SIZE GATE OK: 14232 / 16384 bytes` (2,152 B headroom) and what #34 reclaimed: `BOOT_LOW_FLASH` code at 0x00C0–0x03C7 (776 B; the link fails if it reaches 0x400), the unlinked `r_flash_lp` API table, the GPT fade replaced by a GPIO LED, the FSP `.version` records. The `CAN_DIAG=1` build fits at 14,864 B.
  - **Pre-flash check:** OFS0/OFS1/Security-MPU bytes at 0x400–0x43F against `reference/dfu_minima.hex`.
  - **Flashing:** rfp-cli in ROM boot mode or pyOCD over SWD (stock USB DFU cannot replace the bootloader); unbrick by reflashing `dfu_minima.hex`.
  - **Boot decision:** `VBTBKR[0]` double-tap → USB DFU; `VBTBKR[4]` = `CAN_UPDATE_MAGIC` → CAN-only update mode at 250 kbit/s on D4/D5 with the 15 s idle timeout (update-protocol frames only; before ERASE the old app boots, after it the marker parks the board); otherwise `boot_decide` (valid record → app; failing record or marker → parked DFU + CAN; neither → stock SP check).
  - **Update-in-progress marker:** written after the metadata erase and before the first app erase (CAN `ERASE`, DFU block 0), record written last (CAN `VERIFY`, DFU manifest); a failed marker write refuses the update.
  - **Protocol and config:** Protocol v1, per-device CAN IDs from config block v1/v2 with per-field fallback, the data-flash read-readiness fail-safe, the transceiver-rail power-up (`USBMC.VDCEN` + 5 ms), INFO (`0x07`) wire format, and the CRC record written after a DFU download.
