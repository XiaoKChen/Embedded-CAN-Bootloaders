# src/
> Generated by /map. Do not edit manually — re-run /map to refresh.

Bootloader firmware sources for the Arduino UNO R4 Minima (RA4M1). Split into a
pure-logic core (`boot/`) that is host-compilable/unit-testable, and one
hardware driver (`drivers/`) that feeds it.

## boot/

- **Responsibility:** Pure-C11 bootloader logic — memory map / config constants, image header layout, CRC32, application-image validation, the CAN update protocol state machine, and flash-time DFU name config parsing. No flash or peripheral access anywhere in this directory; every file compiles and unit-tests on the host per `.claude/rules/testing.md`.
- **Key files:** `memory_map.h`, `image_header.h`, `image_validate.{h,c}`, `can_update.{h,c}`, `crc32.{h,c}`, `boot_config.h`, `dfu_config.{h,c}`
- **Relationships:** Depends on nothing outside itself (only `<stdint.h>`/`<string.h>`); consumed by `tests/` (host unit tests) and by the vendored bootloader main (`vendor/arduino-renesas-bootloader/src/main.c`) which supplies the hardware HAL (`can_update_hal_t`) and wires `src/drivers/can_polled.c` frames into `can_update_handle_frame()`.

- **memory_map.h** — Single source-of-truth mirror of the RA4M1 flash/data-flash/SRAM partition (`FLASH_BASE`, `BOOT_BASE`/`BOOT_SIZE`, `APP_BASE`/`APP_SLOT_SIZE`, `METADATA_ADDR`, `DATA_FLASH_BASE`, `DFU_CONFIG_ADDR`, `SRAM_BASE`/`SRAM_END`); enforces consistency via `_Static_assert`. Must match the linker script.
- **boot_config.h** — Compile-time constants for the CAN update transport (`CAN_ID_HOST_TO_BOOT`, `CAN_ID_BOOT_TO_HOST`, `CAN_BITRATE_BPS`) and handoff/image magics (`CAN_UPDATE_MAGIC`, `IMAGE_META_MAGIC`).
- **image_header.h** — Defines the 16-byte little-endian `image_meta_t` record (magic, image_size, image_crc32, header_crc32) stored at `METADATA_ADDR`; includes size/coverage constants and a static-assert on struct size.
- **crc32.h / crc32.c** — `crc32_ieee(data, len)` — IEEE 802.3/zlib-compatible CRC32, table-less bitwise (poly `0xEDB88320`) to save flash.
- **image_validate.h / image_validate.c** — `image_validate(flash_base)`: fail-closed checks in order — metadata magic, header CRC32, image_size bounds, initial SP inside SRAM, Thumb-bit entry point inside the app slot, then payload CRC32 — via explicit little-endian byte loads.
- **can_update.h / can_update.c** — CAN Update Protocol v1 state machine: `can_update_hal_t` (flash HAL seam), phases, and `can_update_init()` / `can_update_handle_frame()`. Windowed DATA buffering into 2048-byte blocks with out-of-order/seq NAK-and-rewind, and a metadata-write-last commit point guaranteeing fail-closed power-loss recovery.
- **dfu_config.h / dfu_config.c** — Frozen 76-byte flash-time DFU name config block (magic, version, mfr/prod length + strings, crc32) at `DFU_CONFIG_ADDR`; `dfu_config_parse()` is fail-closed (magic, version, length bounds, crc32) and returns pointers into the caller's blob. Shared contract with the ESP-Prog-2 provisioning flasher.

## drivers/

- **Responsibility:** Board-specific, polling-only hardware driver layer for the bootloader — currently just the RA4M1 CAN0 peripheral.
- **Key files:** `can_polled.h`, `can_polled.c`
- **Relationships:** Depends on vendored RA4M1/FSP register headers (`vendor/ra4m1-headers/`); supplies raw CAN frames to the bootloader main loop, which feeds them to `boot/can_update.c`. `boot/` never includes `drivers/`.

- **can_polled.h** — `can_polled_status_t` (`OK`/`NO_DATA`/`TIMEOUT`/`BUS_OFF`/`ERROR`) and the API: `can_polled_init(bitrate_bps, rx_filter_id)`, `can_polled_receive()`, `can_polled_send()`, `can_polled_deinit()`.
- **can_polled.c** — Register-level, interrupt-free CAN0 driver: pin mux (D4/D5 → CTX0/CRX0 via PFS), reset→halt→operate sequencing with bounded polling, 250k/500k bit timing (16 tq/bit, 75% sample point), exact single-ID RX-FIFO filtering, single-mailbox TX with bounded SENTDATA polling, and bus-off self-recovery.
