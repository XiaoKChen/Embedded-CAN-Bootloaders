ESP-IDF example projects for the ESP32-S3 boards: a bench OTA test app, a reference node application, and the brain's USB-to-CAN SLCAN bridge firmware, each built against shared components in the repo.

### bench_app/
- **Responsibility:** Minimal OTA application that logs its identity, confirms itself (or deliberately does not) after a self-test, and offers a console command to enter the CAN updater; sends no CAN traffic of its own.
- **Key files:** `main/bench_app.c`, `main/Kconfig.projbuild`, `sdkconfig.defaults`, `sdkconfig.crash_loop`, `sdkconfig.skip_mark_valid`
- **Relationships:** imports from: `can_updater_client` (`can_updater_client_start_health`, `can_updater_client_enter_updater`), `app_update`, `esp_app_format`, `esp_vfs_console`, `../../node_updater/partitions.csv` (via `CONFIG_PARTITION_TABLE_CUSTOM_FILENAME`) — exposes: `app_main`; Kconfig `BENCH_APP_SKIP_MARK_VALID`, `BENCH_APP_CRASH_LOOP`.

- **main/bench_app.c** — Confirms the image with `esp_ota_mark_app_valid_cancel_rollback()` after a heap-integrity self-test, unless `CONFIG_BENCH_APP_SKIP_MARK_VALID` leaves it PENDING_VERIFY; aborts 2 s after boot when `CONFIG_BENCH_APP_CRASH_LOOP` is set; polls stdin so `u` + Enter calls `can_updater_client_enter_updater()`.
- **main/Kconfig.projbuild** — Defines `BENCH_APP_SKIP_MARK_VALID` (rollback test) and `BENCH_APP_CRASH_LOOP` (crash-loop recovery test, depends on not skip).
- **main/CMakeLists.txt** — Registers `bench_app.c` with its private requirements (`can_updater_client`, `app_update`, `esp_app_format`, `esp_vfs_console`).
- **CMakeLists.txt** — Project root: pulls `components/can_updater_client` in via `EXTRA_COMPONENT_DIRS`, sets `COMPONENTS main`, applies the Windows `CMAKE_OBJECT_PATH_MAX 259` workaround.
- **sdkconfig.defaults** — Committed defaults: esp32s3 target, 4 MB flash, custom partition table from `node_updater/partitions.csv`, app rollback enabled, 16-byte custom RTC reserve, USB-Serial-JTAG console.
- **sdkconfig.crash_loop** — Layer for the `crash/` build dir: sets `BENCH_APP_CRASH_LOOP=y` and unsets `SKIP_MARK_VALID`.
- **sdkconfig.skip_mark_valid** — Layer for the rollback-test build: sets `BENCH_APP_SKIP_MARK_VALID=y`.

### node_app/
- **Responsibility:** Reference OTA application template for real node firmware: runs the updater-client health check, provisions its CAN IDs, starts the CAN service, runs a self-test, marks itself valid, and hosts the user's `app_run()` loop.
- **Key files:** `main/node_app.c`, `main/can_service.c`, `main/can_service.h`, `main/Kconfig.projbuild`, `sdkconfig.defaults`
- **Relationships:** imports from: `can_service.h`, `can_updater_client`, `can_link`, `boot_core` (`dfu_config.h`), `src/boot/app_control.c` (APP_INFO/ENTER_UPDATER codec, host-tested), `app_update`, `esp_app_format`, `esp_partition` — exposes: `app_main`; `can_service_load_ids`, `can_service_start`, `can_service_ids_t`; Kconfig `NODE_APP_TWAI_TX_GPIO`, `NODE_APP_TWAI_RX_GPIO`, `NODE_APP_CAN_BITRATE_BPS`.

- **main/node_app.c** — Boot sequence: health start, identity log, load IDs, start CAN service, self-test (`CAN service running` and ID sanity), then `esp_ota_mark_app_valid_cancel_rollback()` on pass; `app_run()` is the placeholder for the node's real work.
- **main/can_service.c** — Runs the CAN service task on TWAI: answers APP_INFO with a multi-frame reply, and handles ENTER_UPDATER by ACKing, deinitialising the link, and calling `can_updater_client_enter_updater()`; NAKs malformed requests and stays silent on updater-only commands. Loads update IDs from the `cancfg` data partition, falling back to 0x79E/0x79F.
- **main/can_service.h** — Public API: `can_service_ids_t` (cmd/reply IDs and `custom` flag), `can_service_load_ids()`, `can_service_start()`; documented as copyable as-is into real node firmware.
- **main/Kconfig.projbuild** — Defines the TWAI TX/RX GPIO (defaults 4/5) and CAN bitrate (default 250000) for the node app; must match the node updater.
- **main/CMakeLists.txt** — Registers `node_app.c`, `can_service.c`, and the shared `../../../src/boot/app_control.c`, with private requirements `can_updater_client`, `can_link`, `boot_core`, `app_update`, `esp_app_format`, `esp_partition`.
- **CMakeLists.txt** — Project root: adds `components/can_updater_client`, `can_link`, and `boot_core` via `EXTRA_COMPONENT_DIRS`; Windows path-length workaround.
- **sdkconfig.defaults** — Committed defaults: esp32s3, 4 MB flash, custom partition table from `node_updater/partitions.csv`, app rollback enabled, 16-byte RTC reserve, USB-Serial-JTAG console.

### slcan_bridge/
- **Responsibility:** Brain-board firmware that exposes the TWAI CAN bus as an SLCAN (Lawicel) adapter over the native USB-Serial-JTAG port, so `tools/can-flash` can reach the node updater with `--interface slcan`.
- **Key files:** `main/slcan_bridge.c`, `main/Kconfig.projbuild`, `main/CMakeLists.txt`, `sdkconfig.defaults`
- **Relationships:** imports from: `can_link` (TWAI wrapper), `node_reset` (node EN line on GPIO3, released at boot and driven LOW), `slcan_codec` (SLCAN parse/encode), `driver/usb_serial_jtag`, `esp_efuse`/`esp_mac` — exposes: `app_main`; Kconfig `SLCAN_BRIDGE_TWAI_TX_GPIO`, `SLCAN_BRIDGE_TWAI_RX_GPIO`, `SLCAN_BRIDGE_BITRATE` choice and `SLCAN_BRIDGE_BITRATE_BPS`.

- **main/slcan_bridge.c** — Two tasks on one core: `usb_to_can_task` splits the USB byte stream into CR-terminated lines and runs commands (C/O/L/Sn/t/T/r/R/V/N) with ACK/NAK replies; `can_to_usb_task` forwards received frames as SLCAN lines and logs bus-state changes, frame loss, and malformed lines; a mutex guards `can_link` teardown.
- **main/Kconfig.projbuild** — Defines TWAI TX/RX GPIO (defaults 6/7), and a bitrate choice (125k/250k/500k/1M; default 250k) that sets `SLCAN_BRIDGE_BITRATE_BPS`, used until the host sends `Sn`.
- **main/CMakeLists.txt** — Registers `slcan_bridge.c` with private requirements `can_link`, `node_reset`, `slcan_codec`, `esp_driver_usb_serial_jtag`.
- **CMakeLists.txt** — Project root: adds `components/can_link`, `node_reset`, and `slcan_codec` via `EXTRA_COMPONENT_DIRS`; Windows path-length workaround.
- **sdkconfig.defaults** — Committed defaults: esp32s3 target; console set to UART0 with no secondary console so logs never mix into the SLCAN stream on USB.
