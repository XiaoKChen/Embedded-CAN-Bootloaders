ESP32-S3 CAN update system (branch `version/c-cpp/esp32`): a **brain**
(ESP32-S3-WROOM-1U-N16R8 + W5500 Ethernet) that updates itself over HTTP and
updates **nodes** (ESP32-S3FH4R2) over classic CAN at 250 kbit/s. Each node runs
a factory CAN updater speaking CAN Update Protocol v1, with button-free recovery
(crash-loop and EN-pulse counters in a 2nd-stage bootloader override) and an
`APP_INFO` / `ENTER_UPDATER` extension for running apps.

## Architecture Overview

- **brain/** — The brain's ESP-IDF firmware (`brain_ota`): W5500 Ethernet HTTP API, A/B self-OTA with self-test rollback, node scan/flash/recover over CAN, and the brain-first update-package relay; 16 MB partition table.
- **node_updater/** — The node's ESP-IDF factory CAN updater app plus its 2nd-stage bootloader override (recovery counters), and the 4 MB partition table every node app shares.
- **components/** — Shared ESP-IDF components: `boot_core` (src/boot in firmware), `can_flash_host`, `can_link` (TWAI), `can_updater_client` (updater entry + recovery health), `node_reset` (GPIO3), `slcan_codec`.
- **examples/** — ESP-IDF example projects: a bench OTA test app, the reference node application, and the brain's USB-to-CAN SLCAN bridge firmware.
- **src/** — The pure-C11, host-testable core (`src/boot/`): Protocol v1 engine, APP_INFO/ENTER_UPDATER codec, boot-counter log, config-block and package parsers, CRC32; no hardware access.
- **tests/** — Host Unity/CTest suite (9 executables) for the pure-logic core, the SLCAN codec and the CAN flash host run against the real node protocol engine.
- **tools/** — Host-side Python tooling: `can_flash.py` (python-can/Textual flasher, scanner and app-control client for the CAN updater) and `ecb_pkg.py` (stdlib-only builder/inspector for update packages).
- **docs/** — Markdown documentation organized into getting-started, concepts, reference, guides and testing (host + bench), with `docs/README.md` as the index.
- **.github/** — One workflow that runs the host tests, builds the node updater, brain and two examples, and publishes a GitHub Release on `c-cpp-esp32-v*` tags.

The pure-logic `src/boot/` core is host-tested in `tests/` and compiled into firmware through `components/`; `node_updater/` and `brain/` are the two board images, `examples/` holds the node apps and the SLCAN bridge, and `tools/` are the PC-side counterparts (CAN flasher and package builder) that talk to them over CAN or the brain's HTTP API.
