### arduino_node_app/
- **Responsibility:** Stock Arduino-ESP32 node-app integration for the factory CAN updater: update IDs and holds from `cancfg`, APP_INFO/ENTER_UPDATER, boot-counter clearing, optional image confirmation.
- **Key files:** `arduino_node_app.cpp`, `include/arduino_node_app.hpp`.
- **Relationships:** Uses the app's existing TWAI driver and the shared `app_control`, `board_profile`, `dfu_config` and `boot_counter` code; compiled only when a PlatformIO environment sets `custom_arduino_node_app = yes` (`platformio/library_build.py`, `library.json`). The app keeps its own `verifyRollbackLater()`.
- **arduino_node_app.cpp** — Loads the CAN IDs and board-profile holds, serves APP_INFO/ENTER_UPDATER from a static core-0 task with a bounded TX wait, clears the boot counter after stable uptime, and optionally confirms a healthy OTA image.
- **include/arduino_node_app.hpp** — Declares the helper's Config, `begin()`, frame dispatch, CAN ID accessors and `confirm_when_healthy()`.

### can_flash_host/

- **Key files:** `can_flash_host.c`, `include/can_flash_host.h`, `CMakeLists.txt`.
- **Relationships:** Uses shared update/app-control definitions and CRC code; callers supply frame I/O, clock, image-read, and optional progress callbacks.

### can_link/
- **Responsibility:** Wraps ESP-IDF TWAI as a configurable CAN link with filtering, frame I/O, health reporting, and bus-off recovery.
- **Key files:** `can_link.c`, `include/can_link.h`, `CMakeLists.txt`.
- **Relationships:** Used by the updater, firmware clients and the SLCAN bridge; encapsulates TWAI/FreeRTOS details behind a C interface.
- **CMakeLists.txt** — Registers the TWAI link driver and declares its component dependencies.
- **can_link.c** — Configures TWAI, handles filtered receive/send, reports bus health, recovers the bus, and drains before teardown.
- **include/can_link.h** — Defines link configuration, frame/status/health types, and the public CAN link API.

### can_updater_client/
- **Responsibility:** App-side entry into the CAN updater and recovery-counter health management for ESP-IDF node apps.
- **Key files:** `can_updater_client.c`, `recovery.c`, `include/can_updater_client.h`, `CMakeLists.txt`.
- **Relationships:** Selects the factory updater partition and restarts; recovery logic uses shared `src/boot/boot_counter.c` and bootloader RTC-retained state.
- **CMakeLists.txt** — Registers the updater-entry and recovery sources with the shared boot-counter implementation and dependencies.
- **can_updater_client.c** — Selects the factory partition as the boot target and restarts into the updater.
- **recovery.c** — Tracks clean restarts, clears recovery counters after stable uptime or verified boot, and preserves latched recovery trips outside factory mode.
- **include/can_updater_client.h** — Declares updater entry and recovery-health APIs and their app integration requirements.

### node_reset/

- **Key files:** `node_reset.c`, `include/node_reset.h`, `CMakeLists.txt`, `Kconfig`.
- **Relationships:** Used by brain firmware to release or pulse the node reset line; the GPIO is selected through Kconfig and configured via ESP-IDF.
- **CMakeLists.txt** — Registers the reset driver and its ESP-IDF dependencies.

- **node_reset.c** — Drives the reset output low for normal operation and generates recovery pulse trains, ensuring a final release attempt.
- **include/node_reset.h** — Defines reset timing constants and declares the release/pulse APIs.
