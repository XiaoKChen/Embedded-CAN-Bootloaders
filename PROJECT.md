ESP32-S3 CAN update system (branch `version/c-cpp/esp32`). **One** 2nd-stage
bootloader and **one** factory CAN updater serve every ESP32-S3 board; what
differs per board (partition table, flash size, TWAI pins and bitrate, GPIOs held
LOW or HIGH from boot, I2C safe writes, USB name and CAN update pair) is data
written by the provisioning tool (ESP-PROG-2-PY-CLI) into the `cancfg` partition:
the frozen v2 DFU block plus a board-profile record (v2: 56 bytes; the 24-byte v1
is still read). The updater speaks CAN Update Protocol v1 at
250 kbit/s, enumerates over TinyUSB with the board's own name, and keeps
button-free recovery (crash-loop and EN-pulse counters in the bootloader
override). A **brain** (the SOLO IDU, or the `brain/` example) updates itself over
Ethernet and updates **nodes** over CAN; running apps answer `APP_INFO` /
`ENTER_UPDATER`, with an opt-in helper for stock Arduino-ESP32 apps.

## Architecture Overview

- **node_updater/** — The shared ESP32-S3 2nd-stage bootloader override and factory CAN updater for every board: early hold-LOW/HIGH GPIOs, the profile's I2C safe writes (bit-banged, best effort) and recovery selection in `boot.c`; TWAI pins, bitrate, holds and the safe writes (repeated every second while parked) from the `cancfg` board profile in `main.c`; a TinyUSB CDC port named from `cancfg` with 1200-baud ROM entry; the node 4 MB and IDU 16 MB tables.
- **brain/** — The brain example's ESP-IDF firmware (`brain_ota`): W5500 Ethernet HTTP API, A/B self-OTA with self-test rollback, node scan (running apps and parked updaters) / flash / recover over CAN, and the brain-first update-package relay (packages ≤ 0x780000).
- **components/** — Shared components: `boot_core`, `can_flash_host`, `can_link` (TWAI), `can_updater_client` (ESP-IDF apps), `node_reset` (GPIO3), `slcan_codec`, and `arduino_node_app` (stock Arduino-ESP32 apps, compiled only with `custom_arduino_node_app = yes`).
- **src/** — The pure-C11, host-testable core (`src/boot/`): Protocol v1 engine, APP_INFO/ENTER_UPDATER codec, board-profile record (v1 and v2) and its bounded bit-banged I2C master, boot-counter log, config-block and package parsers, CRC32; no hardware access.
- **examples/** — ESP-IDF example projects: a bench OTA test app, the reference node application, and the brain's USB-to-CAN SLCAN bridge firmware.
- **tests/** — Host Unity/CTest suite (11 executables) for the pure-logic core, the SLCAN codec and the CAN flash host run against the real node protocol engine.
- **tools/** — Host-side Python: `can_flash.py` (CAN flasher, scanner and app-control client), `ecb_pkg.py` (package builder/inspector) and `updater_bundle.py` (the common release bundle with `manifest.json`).
- **platformio/** — `library_build.py`, which lets a PlatformIO env opt into the node-only helpers.
- **docs/** — Markdown documentation in getting-started, concepts, reference, guides and testing (host + bench), indexed by `docs/README.md`.
- **.github/** — One workflow that runs the host tests, builds the updater, brain and examples, and on `c-cpp-esp32-v*` tags publishes the common `esp32s3-can-updater-<tag>.zip`, the legacy node-updater ZIP and the brain artifacts.

The pure-logic `src/boot/` core is host-tested in `tests/` and compiled into firmware through `components/`, the 2nd-stage bootloader and PlatformIO's `library.json`. `node_updater/` is the one updater every board runs, `brain/` and `examples/` are the board apps, and `tools/` plus ESP-PROG-2-PY-CLI are the PC-side counterparts that build the bundle, provision `cancfg`, and talk to the boards over CAN or the brain's HTTP API.
