# src/

The bootloader's own C sources: a pure-logic, host-testable core under `boot/` (flash/RAM partition, image metadata record and update-in-progress marker, CRC32, image validation and the app-or-park boot decision, the CAN Update Protocol v1 engine, DFU config-block parsing for USB names and per-device CAN IDs) plus the single hardware driver it needs, a polled RA4M1 CAN0 driver under `drivers/`.

## boot/
- **Responsibility:** Pure-C11 logic core: memory-map and config constants, the image metadata layout and marker, CRC32, image validation with `boot_decide()`, the CAN Update Protocol v1 engine, and DFU config-block (v1/v2) parsing. No flash or peripheral access, so every file compiles and is unit-tested on the host.
- **Key files:** `memory_map.h`, `boot_config.h`, `image_header.h`, `crc32.{c,h}`, `image_validate.{c,h}`, `can_update.{c,h}`, `dfu_config.{c,h}`
- **Relationships:** depends only on libc headers. `image_header.h` includes `boot_config.h` and `memory_map.h`; `image_validate.h` includes `image_header.h` and `memory_map.h`; `image_validate.c` and `can_update.c` use `crc32_ieee` and `image_meta_t`; `dfu_config.c` falls back to the `boot_config.h` default CAN IDs. Consumed by `tests/` and by the vendored fork's `src/main.c`, which supplies the flash HAL (including the marker write), calls `boot_decide()`, and runs the CAN service loop (INFO, the idle-timeout reset, the reset after GO). `boot/` never includes `drivers/`.

- **memory_map.h** — Single header mirror of the flash, data-flash and SRAM partition (bootloader 0x0–0x3FFF, app slot at `APP_BASE`, metadata block at `METADATA_ADDR`, `DFU_CONFIG_ADDR`) with `_Static_assert` checks and the VTOR policy. Also defines `BOOT_LOW_FLASH`, a `.text.boot_low_flash` section attribute that places firmware functions in the 0xC0–0x3FF gap between the vector table and the option bytes (no-op on host builds). Must agree with the linker script.
- **boot_config.h** — CAN transport defaults (`CAN_ID_HOST_TO_BOOT` 0x79E, `CAN_ID_BOOT_TO_HOST` 0x79F, `CAN_BITRATE_BPS` 250000), `CAN_UPDATE_IDLE_TIMEOUT_MS` (15000: CAN update mode resets after that long without an update-protocol frame, command byte HELLO..INFO, on the command ID), and the handoff/image magics (`CAN_UPDATE_MAGIC`, `IMAGE_META_MAGIC`).
- **image_header.h** — The 16-byte little-endian `image_meta_t` record (magic, image_size, image_crc32, header_crc32 over the first 12 bytes), and the 8-byte update-in-progress marker at `METADATA_ADDR + IMAGE_PENDING_OFFSET` (`IMAGE_PENDING_MAGIC` + its complement, one write unit), programmed after the metadata erase and before the first app-slot erase; the record is written last.
- **crc32.h / crc32.c** — `crc32_ieee(data, len)`, IEEE 802.3/zlib-compatible, table-less bitwise implementation.
- **image_validate.h / image_validate.c** — `image_validate()` returns `IMAGE_VALID` or the first failure in check order (magic, header CRC, size, initial SP, entry point, payload CRC; frozen `image_validate_result_t`). `boot_decide()` maps that plus the marker to `BOOT_DECISION_APP` / `BOOT_DECISION_PARK`: valid record → app; record failing a later check → park; no record + marker (interrupted update) → park; no record, no marker → stock SP-word fallback.
- **can_update.h / can_update.c** — Hardware-free CAN Update Protocol v1 engine: `can_update_hal_t` (flash HAL), `can_update_init()`, `can_update_handle_frame()`. HELLO/SIZE/ERASE/DATA/VERIFY/GO; ERASE calls the HAL's erase (metadata block + marker, then the app slot); DATA is windowed per 2048-byte block with NAK-and-rewind on a bad seq; VERIFY checks the CRC and writes the record as the commit point; HELLO restarts the session from any phase; command 0x07 (INFO) is handled by the integration layer. The header carries the power-loss table.
- **dfu_config.h / dfu_config.c** — Frozen v1 (76 B) / v2 (80 B) DFU config-block layout (magic, version, manufacturer/product strings, v2 CAN-ID fields, CRC). `dfu_config_parse()` returns the USB strings; `dfu_config_can_ids()` returns the per-device CAN IDs, falling back per field to the `boot_config.h` defaults. Shared contract with the provisioning flasher.

## drivers/
- **Responsibility:** The one peripheral driver the bootloader touches directly: a register-level, polling-only RA4M1 CAN0 driver on D4/D5, no interrupts.
- **Key files:** `can_polled.{c,h}`
- **Relationships:** depends on the vendored RA4M1 headers (`bsp_exceptions.h`, `R7FA4M1AB.h`) and on `../boot/memory_map.h` for `BOOT_LOW_FLASH`. Driven by the fork's `main.c` CAN service loop, which feeds `boot/can_update.c` and takes the RX filter ID from `boot/dfu_config.c`.

- **can_polled.h** — `can_polled_status_t` and the API: `can_polled_init(bitrate_bps, rx_filter_id)`, `can_polled_receive()`, `can_polled_send()`, `can_polled_deinit()`. 250k/500k bit/s, 11-bit standard IDs only, single-ID RX filter.
- **can_polled.c** — Register-level implementation: module-stop release, D4/D5 pin function select through PWPR-guarded PFS writes, reset/halt/operate mode sequencing, 24 MHz PCLKB bit timing, FIFO ID filter, TX through mailbox 0 with a SENTDATA wait, RX through FIFO mailbox 28, bus-off recovery. `can_polled_init`, `can_polled_send` and `can_polled_deinit` are `BOOT_LOW_FLASH` (placed in 0xC0–0x3FF).
