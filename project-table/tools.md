# tools/
> Generated by /map. Do not edit manually — re-run /map to refresh.

Host-side python-can/Textual CLI-and-TUI (`can-flash/can_flash.py`) that flashes
a `.bin` application image to the UNO R4 Minima's custom CAN bootloader over
classic CAN 2.0B via the CAN Update Protocol v1, and can also identify, scan
for, and remotely reboot Airform-based boards into that bootloader.

### tools/
- **Responsibility:** Houses standalone host-side tooling that is not part of the firmware build; currently a single CAN flashing/administration tool.
- **Key files:** `tools/can-flash/can_flash.py`
- **Relationships:** speaks the same CAN Update Protocol v1 implemented in `src/boot/can_update.c`; no build-system dependency on the rest of the repo (self-contained Python script).

### tools/can-flash/
- **Responsibility:** A single-file, `uv run`-able Python tool (PEP 723 inline deps) that is both a headless CLI and a Textual TUI for flashing, identifying, scanning, and remotely rebooting boards running the UNO R4 Minima CAN bootloader (Protocol v1).
- **Key files:** `can_flash.py`, `README.md`, `requirements.txt`
- **Relationships:** imports `can` (python-can), `isotp` (can-isotp, lazy-imported only for `--enter-bootloader`), and `textual` (App/widgets for the TUI); protocol constants (`CMD_HELLO`..`CMD_INFO`, error codes, frame geometry) mirror `src/boot/can_update.c`/`src/boot/dfu_config.c` on the firmware side.

- **can_flash.py** — The entire tool. Defines the CAN Update Protocol v1 constants (`CMD_HELLO 0x01`..`CMD_GO 0x06`, `CMD_INFO 0x07`, error codes, `FLASH_BLOCK_SIZE`/window framing, `EXPECTED_SLOT_SIZE`); `class CanFlasher` (methods `hello`, `send_size`, `erase`, `send_image`, `verify`, `go`, `query_info`) driving the protocol over a `can.Bus`; `flash_image()` orchestrating the full HELLO→GO flow with pluggable `log`/`progress` callbacks; discovery helpers `build_scan_ids`, `probe_info`, `scan_boards`, `print_scan_table` for `--scan` (broad-listen INFO probe across a candidate cmd-ID band plus `KNOWN_DEVICE_CMD_IDS`); `encode_uart_packet()` and `enter_bootloader()` implementing the Airform `/enter_bootloader` ISO-TP RPC (via `can-isotp`) for `--enter-bootloader`; `class FakeBootloader(threading.Thread)` plus `run_selftest()`/`run_scan_selftest()`/`run_tui_smoke_test()`/`check_enter_bootloader_vector()` implementing `--selftest` (in-process protocol simulation on python-can's `virtual` interface, no hardware needed); the Textual TUI (`class FlasherApp(App)`, `class BinPickerScreen(ModalScreen)`, `class _BinDirectoryTree(DirectoryTree)`, `run_tui()`) launched by bare invocation or `--tui`; and the CLI entry point (`parse_args()`, `load_image()`, `main()`) that routes between TUI and headless execution based on argv.
- **README.md** — Usage documentation: wiring (external 5V CAN transceiver required on D4/D5), TUI vs. headless CLI invocation, entering CAN update mode (app-triggered handoff word `0xB007CAFE` in `VBTBKR[4]`, or no valid app present), `--enter-bootloader` RPC details (Uart_Packet/ISO-TP framing, board RX/TX IDs), `--scan` multi-board discovery workflow and the known-device cmd-ID band, the full CLI options table, `--selftest` description, and the Protocol v1 wire-format summary (command bytes, ACK/NAK layout, window/frame sizing).
- **requirements.txt** — Pin list for `pip install`-based (non-`uv`) setup: `python-can>=4.0`, `can-isotp>=2.0`, `textual>=0.60`.
