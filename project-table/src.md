# src/

The bootloader's own C sources: a pure-logic, host-testable core under `boot/` (flash/RAM partition, image metadata record and update-in-progress marker, CRC32, image validation, the app-or-park boot decision and update-start plan, the CAN Update Protocol v1 engine, DFU config-block parsing for USB names and per-device CAN IDs) plus the single hardware driver it needs, a polled RA4M1 CAN0 driver under `drivers/`.

## boot/
- **Responsibility:** Pure-C11 logic core: memory-map and config constants, the image metadata layout and marker, CRC32, image validation / staged-commit check / `boot_decide()` / `update_start_plan()`, the CAN Update Protocol v1 engine, and DFU config-block (v1/v2) parsing. No flash or peripheral access (flash goes through an injected HAL), so every file compiles and is unit-tested on the host.
- **Key files:** `memory_map.h`, `boot_config.h`, `image_header.h`, `crc32.{c,h}`, `image_validate.{c,h}`, `can_update.{c,h}`, `dfu_config.{c,h}`
- **Relationships:**
  - **Dependencies:** libc headers only.
    - `image_header.h` uses `memory_map.h` and `boot_config.h`.
    - `image_validate.*` uses `image_header.h`, `memory_map.h` and `crc32.h`.
    - `can_update.*` uses `boot_config.h`, `memory_map.h`, `image_header.h` and `image_validate.h`.
    - `dfu_config.c` uses `crc32.h` and falls back to the `boot_config.h` defaults.
  - **Exposes:** `image_validate`, `image_check_bounds`, `image_check_staged`, `image_meta_encode`, `boot_decide`, `update_start_plan`, `can_update_*`, `dfu_config_parse`, `dfu_config_can_ids`, `crc32_ieee`, `crc32_ieee_update`.
  - **Consumers:** `tests/`, and the vendored fork's `src/main.c`, which:
    - supplies the flash HAL (including the marker write and `flash_locked`);
    - calls `boot_decide()` / `update_start_plan()`;
    - answers INFO;
    - runs the idle timeout, the ownership timeout and the reset after GO.
  - `boot/` never includes `drivers/`.

- **memory_map.h** — Single header mirror of the flash, data-flash and SRAM partition:
  - bootloader 0x0–0x3FFF, `APP_BASE` 0x4000, `APP_SLOT_SIZE` 0x3B800, `METADATA_ADDR` 0x3F800;
  - 2048 B erase block, 8 B write unit;
  - `DFU_CONFIG_ADDR` 0x40101C00, SRAM 0x20000000 + 32 KB.

  It carries `_Static_assert` layout checks and the VTOR policy, and must agree with the linker scripts (`ra4m1_minima_boot.ld` holds the 16 KB bound). It also defines `BOOT_LOW_FLASH`, a `.text.boot_low_flash` section attribute that places functions in the 0xC0–0x3FF gap below the option bytes (empty on host builds).
- **boot_config.h** — CAN defaults and timing constants:
  - `CAN_ID_HOST_TO_BOOT` 0x79E, `CAN_ID_BOOT_TO_HOST` 0x79F, `CAN_BITRATE_BPS` 250000;
  - `CAN_UPDATE_IDLE_TIMEOUT_MS` (20000): CAN update mode resets after this long without an accepted update-protocol frame, and the parked loop uses the same bound as its flash-ownership timeout. It must exceed the hosts' 15 s ERASE wait;
  - `CAN_REINIT_INTERVAL_MS` (1000): how often `can_polled_init()` is retried while CAN is down;
  - the magics `CAN_UPDATE_MAGIC` (0xB007CAFE, the VBTBKR[4] handoff) and `IMAGE_META_MAGIC`.
- **image_header.h** — Record and marker layouts:
  - the 16-byte little-endian `image_meta_t` record: magic, image_size, image_crc32, and header_crc32 over the first 12 bytes;
  - `IMAGE_MIN_SIZE` (8);
  - `IMAGE_VECTOR_UNIT_SIZE`: the image's first 8 bytes (SP + reset vector), held in RAM until commit;
  - the 8-byte update-in-progress marker at `METADATA_ADDR + IMAGE_PENDING_OFFSET` (`IMAGE_PENDING_MAGIC` + its complement), with static asserts on its placement and the three update-start orders documented.
- **crc32.h / crc32.c** — `crc32_ieee(data, len)` and incremental `crc32_ieee_update(crc, data, len)`; IEEE 802.3 / zlib-compatible, table-less bitwise.
- **image_validate.h / image_validate.c**
  - **`image_validate()`:** returns `IMAGE_VALID` or the first failure in check order (magic, header CRC, size, initial SP, entry point, payload CRC; frozen `image_validate_result_t`).
  - **`image_check_bounds()`:** SP in (SRAM_BASE, SRAM_END] and 8-byte aligned; entry point with the Thumb bit set, inside the image and past the vector words.
  - **`image_check_staged()`:** the commit check. It bounds-checks the RAM vector unit, then CRCs the vector unit plus the flash remainder.
  - **`image_meta_encode()`:** the single record encoder.
  - **`boot_decide()`:** valid record → app; record present but a later check fails → park; no record + marker → park; no record and no marker → the stock SP-word fallback.
  - **`update_start_plan()`:** returns `UPDATE_START_MARKER_IN_PLACE`, `_ERASE_METADATA` or `_ERASE_APP_THEN_METADATA`, so no erase prefix can let the fallback boot a partial image.
- **can_update.h / can_update.c** — The hardware-free CAN Update Protocol v1 engine.
  - **HAL and API:**
    - HAL `can_update_hal_t`: `flash_erase_app_and_metadata`, `flash_program`, `flash_base`, `flash_locked`.
    - `can_update_init()` and `can_update_handle_frame()`.
    - `can_update_accepts_frame()`: command ID, DLC 8, command 0x01..0x07, 0xFF padding; DATA only during a transfer or as a resend of the final window.
    - `can_update_owns_flash()` and `can_update_end_session()`.
  - **Behaviour:**
    - SIZE/ERASE/DATA/VERIFY NAK 0x05 while USB DFU owns flash.
    - DATA is windowed per 2048-byte block, with NAK-and-rewind on a bad seq.
    - Block 0's vector unit is held in RAM. VERIFY runs `image_check_staged()`, programs the vector unit, then writes the record as the commit point.
    - Exact repeats of SIZE/ERASE/VERIFY and of the last DATA window are re-ACKed; HELLO restarts from any phase.
    - Flash failures drop the session to IDLE.
  - The header carries the power-loss table.
- **dfu_config.h / dfu_config.c** — The frozen v1 (76 B) / v2 (80 B) DFU config-block layout: magic, version, manufacturer/product strings, v2 CAN command/reply IDs, CRC.
  - `dfu_config_parse()` returns the USB strings or a status error.
  - `dfu_config_can_ids()` always yields usable IDs, falling back per field to the `boot_config.h` defaults for a v1 or invalid block, an out-of-range ID, or cmd == reply.
  - It is a shared contract with the provisioning flasher.

## drivers/
- **Responsibility:** The one peripheral driver the bootloader touches directly: a register-level, polling-only RA4M1 CAN0 driver on D4 (CTX0, P103) / D5 (CRX0, P102), no interrupts.
- **Key files:** `can_polled.{c,h}`
- **Relationships:** depends on the vendored RA4M1 headers (`bsp_exceptions.h`, `R7FA4M1AB.h`) and on `../boot/memory_map.h` for `BOOT_LOW_FLASH`. Driven by the fork's `main.c` CAN service loop, which feeds `boot/can_update.c` and takes the RX filter ID from `boot/dfu_config.c`.

- **can_polled.h** — API and statuses:
  - **Statuses:** `can_polled_status_t` (`CAN_POLLED_OK`, `_NO_DATA`, `_TIMEOUT`, `_BUS_OFF`, `_ERROR`, `_RECOVERY_FAILED`).
  - **API:** `can_polled_init(bitrate_bps, rx_filter_id)` (250k/500k only), `can_polled_receive()`, `can_polled_send()`, `can_polled_deinit()`.
  - **Bus settings:** 11-bit standard IDs, an exact single-ID RX filter, 16 tq/bit, SJW 4 tq, 75 % sample point (about 0.98 % clock tolerance from the HOCO-derived 24 MHz PCLKB).
  - **Time base:** it owns the DWT cycle counter and leaves it running.
- **can_polled.c** — Register-level implementation:
  - module-stop release, D4/D5 PFS pin select, reset/halt/operate mode sequencing, BCR bit timing (prescalers derived from PCLKB and asserted);
  - FIFO mailbox mode with a FIDCR/MKR filter on mailboxes 28–31;
  - TX through mailbox 0: made idle before each send, with an abort waited out.
  - **Timeouts:** every wait is bounded on the DWT cycle counter (mode switch 10 ms, TX 200 ms, abort 2 ms), with a poll-count fallback.
  - **Bus-off:** the controller's automatic ISO 11898-1 recovery runs (reported as `CAN_POLLED_BUS_OFF`). A bus-off over 1 s forces a re-init, and a failed re-init latches `CAN_POLLED_RECOVERY_FAILED`.
  - **Deinit order:** reset mode → pins back to GPIO → module stop.
  - `can_polled_init`, `can_polled_send` and `can_polled_deinit` are `BOOT_LOW_FLASH`.
