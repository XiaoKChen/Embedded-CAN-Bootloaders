### tests/
- **Responsibility:** Standalone CMake+CTest project (`bootloader_host_tests`) that builds `src/boot/*.c` as a `boot_core` static library with zero hardware includes, links each `test_*.c` against it plus vendored Unity, and registers each as a CTest test. Runs on x86 — no target toolchain needed.
- **Key files:** `CMakeLists.txt`, `test_crc32.c`, `test_image_validate.c`, `test_can_update.c`, `test_dfu_config.c`
- **Relationships:** imports from `src/boot/` (crc32, image_validate, can_update, dfu_config — including both `dfu_config_parse` for USB names and `dfu_config_can_ids` for per-device CAN IDs); depends on `tests/unity/`. Consumable standalone (`cmake -S tests -B build-host`) or via `add_subdirectory(tests)` from the root build.

- **CMakeLists.txt** — C11 project; builds vendored `unity` and a `boot_core` lib from the `src/boot` sources, and defines `add_host_test(name)` to compile/link/register each `test_*.c` as a CTest test.
- **test_crc32.c** — Golden-vector tests for `crc32_ieee` (standard "123456789" check value, empty input, single byte, all-0xFF write unit, one-shot guard).
- **test_image_validate.c** — Exercises `image_validate()` against a fake 256 KB flash buffer; covers every result — valid, bad magic, header-CRC corruption, size zero/below-min/above-slot/at-boundary, SP below/at-base/above-end, entry in bootloader/metadata region/Thumb-clear, payload-CRC corruption.
- **test_can_update.c** — Drives `can_update_handle_frame()` against a fake NOR-flash HAL enforcing erase-before-program and write alignment; covers the full happy path, wrong CAN ID, wrong version, out-of-order commands, size-OOB NAKs, seq-gap rewind, VERIFY CRC mismatch (metadata left erased), injected flash failures with recovery, HELLO restart mid-transfer, and malformed DLC.
- **test_dfu_config.c** — Tests `dfu_config_parse()` and `dfu_config_can_ids()` against an 80-byte fake config blob (fits both v1/76B and v2/80B records). Name parsing: valid v1 round-trip, v2 round-trip, erased/bad magic, bad version, over-max/at-max lengths, bad CRC (v1 and v2), mutated payload, empty-string boundary. Per-device CAN IDs: v1/no-block fall back to `boot_config.h` defaults; a valid v2 block yields provisioned IDs; boundary IDs (0x000 / `DFU_CONFIG_CAN_ID_MAX`) accepted; out-of-range IDs fall back per-field; a mixed valid/invalid pair falls back only the bad field; the v2 CRC covers the ID fields (mutating an ID without re-CRC fails); a bad-CRC v2 block leaks no IDs (defaults only).
